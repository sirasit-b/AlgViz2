# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

AlgoViz is a static, dependency-free PHP site that visualizes algorithms and data structures step-by-step (Play/Pause, step forward/back, scrubber). Vanilla HTML/CSS/JS engine, anime.js for tweening, three.js for the catalog hero background only. No framework, no bundler, no npm/composer dependencies — the only build tool is a small Node script that concatenates source files.

## The one rule that matters

**`src/` is the only source of truth.** `assets/algoviz.css`, `assets/algoviz.js`, `assets/app.html`, `config/topics.php`, and `preview.html` are generated by the build and are committed intentionally (so a clone can deploy without a build step) — but editing them by hand is pointless because the next build overwrites them. Always edit under `src/`, then rebuild:

```bash
node build/build.mjs
```

## Commands

```bash
# Rebuild generated assets after any change under src/ (required before testing)
node build/build.mjs

# Local dev server with pretty URLs (router.php shims php -S to behave like .htaccess)
php -S 127.0.0.1:8088 -t . router.php
#   http://127.0.0.1:8088/            -> catalog
#   http://127.0.0.1:8088/quick-sort  -> a visualizer page

# Docker equivalent (PHP 8.3 + Apache + mod_rewrite/mod_expires, matches production)
docker compose run --rm build   # runs node build/build.mjs inside the container
docker compose up -d --build    # serve at http://localhost:8088
docker compose logs -f web
docker compose down
```

There is no test suite, linter, or type checker in this repo — validation is: build succeeds with no errors, `git status` is clean afterward (no stray unbuilt changes), and the topic works in a real browser (menu entry, own URL, Play/Pause/step, custom input).

Quick look without PHP: open `preview.html` directly in a browser (it self-contains everything and uses hash routing instead of pretty URLs — fine for a fast visual check, but not for testing real URL/SEO behavior).

## Build pipeline (`build/build.mjs`)

Source → output mapping:

| Source (edit here) | Generated output (never hand-edit) |
|---|---|
| `src/core.head.html` (`<style>` block) | `assets/algoviz.css` |
| `src/core.body.html` (markup + engine IIFE) | `assets/app.html`, `assets/algoviz.js` |
| `src/renderers/*.js` | inlined into `assets/algoviz.js` at the `@@RENDERERS_EXT@@` marker |
| `src/content/**/*.js` | inlined into `assets/algoviz.js` at the `@@CONTENT@@` marker |
| (parsed from all `AlgoViz.register({...})` calls) | `config/topics.php` |
| all of the above | `preview.html` (standalone, hash-routed) |

The build parses `id`, `cat`, `difficulty`, `nameTh`, `nameEn`, `blurb` out of each `AlgoViz.register({...})` call with regex (not a JS parser) to produce `config/topics.php` — so those fields must stay as literal strings/numbers on their own regex-matchable form (`id: 'my-algo'`, `cat: 'sort'`, `difficulty: 2`, etc.), not computed expressions.

`index.php`, `partials/*.php`, `.htaccess`, and `config/taxonomy.php` are hand-authored and are **not** touched by the build.

## Runtime architecture

**Request flow:** `.htaccess` routes every request that isn't a real file to `index.php` (dev: `router.php` shims the same behavior for `php -S`). `index.php` looks up the URL path as a topic id in `config/topics.php`, sets per-topic `<title>`/OG/canonical tags and a `<noscript>` sitemap (built from `config/taxonomy.php`), includes `partials/head.php` and the built `assets/app.html` markup, then `partials/footer.php` injects `window.AV_BASE`/`window.AV_INITIAL` and loads `assets/algoviz.js`. From there it's a client-side SPA: the JS router uses the History API for pretty URLs when served via PHP, falling back to hash routing when opened as `file://` (i.e. `preview.html`).

**Step-generator + Player, in `assets/algoviz.js` (built from `src/core.body.html`):**

```
AlgoViz.register({...})  ->  mountControls(host, ctx)  ->  frames[]  ->  ctx.load(frames)  ->  Player  ->  RENDERERS[renderer]
```

- Each topic's `mountControls` builds its own input UI, computes a full `frames[]` array up front (one snapshot per step: `note`, `line` for pseudocode highlighting, `stats`, plus renderer-specific state), and hands it to the shared `Player` via `ctx.load(frames)`. Play/pause/step/scrub/speed are entirely generic — a topic never implements its own playback controls.
- `RENDERERS` is a registry of draw functions keyed by name, split into families: `core` renderers (`bars`, `array`, `stack`, `queue`, `linkedlist`, `hash`, `tree`, `graph`, `hanoi`, `calltree`) live directly in `src/core.body.html`; the `net` family (`sequence`, `statemachine`) lives in `src/renderers/net.js`. Each renderer draws with SVG/DOM given a frame's state.
- Topic metadata (`cat`) must match a field id defined in **both** `CATS` in `src/core.body.html` (client-side taxonomy/menu) and `fields` in `config/taxonomy.php` (server-side SEO/sitemap) — these two are hand-kept in sync, the build does not generate one from the other.

**Adding a new visualizer:** drop a `.js` file anywhere under `src/content/<domain>/` (`cs`, `cpe`, or `se`) calling `AlgoViz.register({...})` (see `src/content/cpe/networking.js` for a full real example), then run `node build/build.mjs`. The catalog entry, URL routing, and SEO metadata are all derived from the registration call — no other wiring is needed. Full field-by-field reference (valid `cat`/`renderer` values, frame shape, difficulty scale) is in [CONTRIBUTING.md](CONTRIBUTING.md).

**Adding a new renderer family:** add `RENDERERS.<name> = function(){...}` in a new or existing file under `src/renderers/`; the build inlines any file there automatically.

## Git workflow

Two-tier branching: `feat/<name>` / `fix/<name>` / `docs/<name>` branches off `dev` → PR into `dev` → `dev` merges into `main` once stable. Never push directly to `main`. Commit the build output (`assets/*`, `config/topics.php`, `preview.html`) alongside source changes — this repo intentionally commits generated files so a clone can deploy without running a build.
